DiscordのAIボットを無料で作る方法 ― 最初から最後までの手順

公開日：2026-11-26（情報確認日：2026-11-26）

この記事には、将来的にアフィリエイト広告（PR）を含む場合があります。現在は広告リンクを設置していません。

この記事について

この記事は、筆者が実際にDiscordのAIボットを構築し、現在も運用している経験をもとに書いた手順書です。「どんな仕組みか」の説明だけではなく、どの画面で何を押して、何を入力すればいいかまで、順番に書いていきます。読み終わったあと、そのまま同じ手順で自分のボットを動かせる粒度を目指しました。

使うのは無料枠のあるサービスだけです。クレジットカードの登録は一切していません。かかる費用は0円です。

先に完成像を書いておきます。出来上がるのは、DiscordのサーバーでメンションするとAIが答えてくれるボットです。普通の質問への回答に加えて、「調べて」と頼むとWeb検索をして出典付きで答えたり、為替や株価・天気のような「今の数字」を専用の取得先から取ってきて答えたりします。会話のしかたも2種類用意しました。チャンネルでメンションして1問1答する使い方と、スレッドの中で文脈を引き継いで続けて話す使い方です。

なお、無料枠には必ず「癖」があります。上限がある、眠る、といった癖です。この記事では、癖にぶつかった実例と、どう回避したかも含めて書きます。各サービスの無料枠・条件は2026年11月時点の情報です。変わることがあるので、始める前に公式サイトで最新条件を確認してください。

全体の流れと、必要な部品

ボットは4つの部品でできています。

  1. Discord：ボットと話す場所。ボットの作成自体は無料です
  2. Gemini（GoogleのAI）：質問に答える頭脳。Google AI StudioでAPIキーを発行し、無料枠を使います
  3. GitHub：ボットのプログラム（コード）を置く場所。公開リポジトリを使います
  4. Render：プログラムを動かし続ける場所。無料のWebサービス枠を使います

データの流れは「Discordでメンションが飛ぶ → Render上のプログラムが受け取る → Geminiに質問を渡す → 答えが返ってくる → Discordに投稿する」です。

作業の順番は次のとおりです。

手順1：Discordでボットの「入れ物」を作る手順2：ボットを自分のサーバーに入れる手順3：GeminiのAPIキーを用意する手順4：プログラムを書いてGitHubに置く手順5：Renderで公開する（環境変数の設定が山場です）手順6：Discordで動作確認する

事前に用意するものは、Discordアカウント、Googleアカウント、GitHubアカウントの3つだけです。どれも無料で作れます。筆者はこのボット専用にGoogleアカウントを1つ作り、GitHubやRenderの登録にもそのアカウントを使いました。普段使いのアカウントと分けておくと、後から管理が楽です。

手順1：Discordでボットの「入れ物」を作る

まず、Discord Developer Portal（開発者向けの管理画面）でボットの実体を作ります。

  1. ブラウザでDiscord Developer Portalを開き、普段のDiscordアカウントでログインします
  2. 右上の「New Application」ボタンを押し、アプリケーションの名前を入力して作成します。この名前がそのままボットの表示名になります。後から変更もできますが、最初から付けたい名前で作るのが楽です
  3. 左側のメニューから「Bot」を開きます。ここにボットのユーザー情報が表示されます
  4. 「Reset Token」ボタンを押すと、Botトークン（長い文字列）が表示されます。これがボットの「鍵」です。この後の手順5でRenderの環境変数に入れるので、安全な場所に控えてください。トークンは一度しか表示されません。再表示するにはリセットが必要で、リセットすると古いトークンは使えなくなります
  5. 同じ「Bot」の画面を下にスクロールすると「Privileged Gateway Intents」という項目があります。その中の「MESSAGE CONTENT INTENT」をオンにして保存します

つまずきやすいのは5番です。ボットがメッセージの本文を読むには、この設定が必須です。オフのままだと、メンションされても本文が空っぽで届くため、ボットが何を聞かれたのか分かりません。「ボットが反応はするのに、質問を理解してくれない」という症状が出たら、まずここを疑ってください。

もう1つ、トークンの扱いについて。トークンが漏れると、第三者にボットを乗っ取られます。コードの中に直接書いたり、公開した場所に貼ったりするのは絶対に避けてください。具体的な守り方は手順4と手順5で説明します。

手順2：ボットを自分のサーバーに入れる

入れ物ができたら、招待URLを作って自分のDiscordサーバーに追加します。

  1. Developer Portalの左メニューから「OAuth2」→「URL Generator」を開きます
  2. 「SCOPES」の一覧で「bot」にチェックを入れます
  3. 下に「BOT PERMISSIONS」の一覧が出るので、必要な権限にチェックを入れます。筆者のボットでは、メッセージの読み書き、スレッドの作成、履歴の閲覧など、チャットボットとして必要な範囲を選んだ結果、権限値（Permissions Integer）は 377957189632 になりました
  4. 画面の下に生成されたURLをコピーし、ブラウザで開きます
  5. 追加先のサーバーを選び、「認証」ボタンを押します。このとき、そのサーバーで「サーバー管理」権限を持っている必要があります。自分のサーバーなら問題ありません

認証が終わると、サーバーのメンバーリストにボットが現れます。ただし、この時点ではまだプログラムが動いていないので、話しかけても返事は来ません。心臓部はこれから作ります。

つまずきやすい点として、URL Generatorで選ぶ権限が足りないと、後から「メッセージは送れるのにスレッドが作れない」のような部分的な不具合になります。後から権限を足すこともできますが、その場合は招待URLを作り直して、もう一度サーバーへの追加（認証）が必要です。

手順3：GeminiのAPIキーを用意する ― ここに大きな落とし穴がありました

次に、頭脳であるAIを用意します。Google AI StudioでAPIキーを発行します。

  1. ブラウザでGoogle AI Studioを開き、Googleアカウントでログインします
  2. 「Get API key」（APIキーを取得）を押し、「Create API key」でキーを発行します
  3. 発行されたキーを控えます。これも手順5でRenderの環境変数に入れます。コードには書きません

ここで、筆者が実際にぶつかった一番大きな落とし穴を書きます。「どのモデルを使うか」です。

最初、筆者は gemini-2.0-flash というモデルを使う前提で構築を進めました。ところが、いざ動かしてみるとエラーになります。調べると、このプロジェクトでは gemini-2.0-flash の無料枠の割り当て自体が「0」だったのです。つまり、無料では1回も呼べない設定になっていました。

教訓はシンプルで、「モデルの無料枠は、モデルごとに別々に決まっている」ということです。評判の良いモデルを選んでも、自分のプロジェクトで無料枠が付いているとは限りません。AI Studioのレート制限の画面で、モデルごとに当日の上限と使用数が確認できるので、構築前に必ず目当てのモデルの無料枠が「0でないこと」を確認してください。

筆者は最終的に gemini-3.5-flash-lite という軽量モデルに切り替えて、本番運用しています。2026年11月時点の無料上限は、15 RPM（1分あたり15リクエスト）／250K TPM（1分あたり25万トークン）／500 RPD（1日あたり500リクエスト）です。個人で使うチャットボットなら、1日500リクエストでも十分に回ります。同じ上限の付いた別の軽量モデルも予備として確認してあるので、片方が使えなくなっても切り替えられる状態にしています。

APIキーの利用状況（今日何回使ったか）は、AI Studioの使用量・レート制限のページでいつでも確認できます。「あと何回使えるか」が見える状態にしておくと、上限に当たって突然止まる事故を防げます。

手順4：プログラムを書いてGitHubに置く

頭脳と入れ物が揃ったら、両者をつなぐプログラムを用意します。プログラム本体の書き方（コード全文）は本記事の範囲外としますが、構成と守るべきルールは具体的に書きます。

リポジトリ（GitHub上の置き場所）は公開リポジトリで作りました。ファイル構成は最小限で、次のような形です。

  • main.py：プログラム本体。Discordへの接続、メッセージの受け取り、Geminiへの問い合わせ、返信の投稿までを担当します
  • requirements.txt：使うライブラリの一覧。Renderが自動でインストールするために必要です

ここで絶対に守るルールが1つあります。BotトークンとGeminiのAPIキーを、コードの中に直接書かないことです。コードは公開リポジトリに置くので、キーを書いた瞬間に世界中へ公開されます。実際に、公開リポジトリに上げられたキーは短時間で第三者に拾われると言われています。

代わりに、プログラム側では「環境変数から読み取る」書き方にしておきます。環境変数とは、実行する場所（この場合はRender）の側にだけ値を置ける仕組みです。こうしておけば、コードは公開しても安全で、鍵はRenderの中にだけ存在する状態になります。手順5でその設定を行います。

もう1つ、設計の段階で決めておくと後が楽なのが「会話履歴をどうするか」です。筆者のボットでは、履歴はプログラムのメモリ上にだけ持つことにしました。割り切った設計ですが、代償として、プログラムを再起動（再デプロイ）すると会話の記憶はリセットされます。無料枠で回す範囲では、この割り切りで実用上問題ありませんでした。

手順5：Renderで公開する ― 環境変数の設定が山場

プログラムを24時間動かす場所として、Renderの無料Webサービスを使います。

  1. Renderにログインし、「New」→「Web Service」を選びます
  2. 接続方法の選択では、GitHubアカウント連携ではなく「Public Git Repository」（公開リポジトリのURL指定）を選び、手順4のリポジトリURLを入力します。筆者はこの方式にしました。理由は後述します
  3. 設定項目を入力します。主なものは次のとおりです

　- Runtime：Python 3　- Build Command：pip install -r requirements.txt　- Start Command：python main.py　- Instance Type：Free（無料枠）

  1. 「Environment Variables」（環境変数）の欄に、秘密情報を登録します。登録したのは主に次の3つです

　- DISCORD_TOKEN：手順1で発行したBotトークン　- GEMINI_API_KEY：手順3で発行したAPIキー　- GEMINI_MODEL：使うモデルの名前（gemini-3.5-flash-lite）

  1. 「Create Web Service」を押すと、初回デプロイ（公開作業）が始まります。数分待ってログにエラーが出なければ公開完了です

つまずきやすい点を3つ書きます。

1つ目は、デプロイ方式の違いです。手順2で述べたとおり、筆者はGitHub連携ではなく公開リポジトリURLの指定で接続しました。この方式では、GitHubにコードをpushしても自動ではデプロイされません。コードを直したら、Renderの管理画面で手動の再デプロイが必要です。「直したはずなのにボットの動きが変わらない」というときは、ほぼ再デプロイ忘れです。なお、Renderの再デプロイは変更のたびに行わず、ある程度変更が固まってからまとめて行う運用にしています。再デプロイのたびに会話履歴がリセットされることと、無料枠の都合が理由です。

2つ目は、環境変数の名前の一致です。プログラム側で読み取る名前と、Renderに登録する名前が1文字でも違うと、値は届きません。「トークンが読み取れず起動直後に落ちる」という症状は、だいたいここか、値の前後に空白が混ざっていることが原因です。

3つ目は、ログの見方です。デプロイ直後はRenderのログ画面を開いたままにしてください。起動に成功したか、どの行でエラーになったかは、すべてここに出ます。筆者も、プログラムの標準出力が溜まって表示されない問題に気づいたのはログを見ていたからで、行単位で即時出力する設定に直して解決しました。動かないときは、Discord側ではなくまずRenderのログを見るのが近道です。

公開が完了すると、RenderがサービスのURLを発行します。ルートにアクセスすると応答が返り、死活確認用の /health というURLも用意しました。この /health が、後述するスリープ対策の要になります（詳しくは「無料サーバーはなぜ眠るのか」の記事にまとめました）。

手順6：Discordで動作確認する

公開できたら、いよいよ確認です。筆者は本番のサーバーでいきなり試さず、テスト専用のサーバーと「bot検証」という専用チャンネルを用意して、そこで確認しました。失敗しても周りに迷惑がかからない場所を持つのは、地味ですが大事です。

確認の手順は次のとおりです。

  1. テスト用チャンネルで、ボットにメンションして簡単な質問を送ります（例：「@ボット こんにちは」）
  2. 返事が返ってくれば、Discord → Render → Gemini の経路が全部つながっています
  3. 返事が来ない場合は、切り分けます。Renderのログにアクセスの形跡があるか（プログラムは起きているか）→ 環境変数は正しいか → 手順1の MESSAGE CONTENT INTENT はオンか、の順に確認します
  4. 続けて、スレッドの開始コマンドや検索の開始フレーズなど、機能ごとの入口を1つずつ試します

筆者の環境では、メンションへの返事は通常数秒〜十数秒で返ってきました。初回だけ極端に遅い場合は、Renderのスリープから復帰中である可能性が高いです（これもスリープ対策の記事で詳しく扱います）。

応答の仕様は「入口」を分けて決める

動くようになったら、次は「どう答えるか」の仕様です。筆者は入口ごとに振る舞いを分けました。ここを最初に決めておくと、後からの機能追加で混乱しません。

  1. 通常のメンション：そのチャンネルで1問1答します。会話履歴は持たず、スレッドも作りません。ちょっとした質問にすぐ答えるための入口です
  2. /thread コマンド：引数に質問を渡すとスレッドを作り、その中ではメンションなしで会話を続けられます。履歴を引き継ぐので、相談や作業の続きに向いています
  3. 検索：文頭が「調べて」「検索して」で始まるメッセージ、または /search コマンドで、Web検索（Tavilyという検索サービス。無料枠は月1,000クレジット、2026年11月時点）を使って調べ、出典のURLを付けて答えます。最初からAIに「分からないことは検索結果に基づいて答える」よう指示しておくのがコツです

さらに、「今の数字」が要る質問は、検索とは別の取り方をしています。検索結果に出てくる為替や株価の数字は、少し古いことがあるためです。

  • 為替・主要な株価指数・ビットコイン：Yahoo FinanceのチャートAPIから直接取得します。為替は取得できない場合の予備として、別の為替レートAPIも用意しました
  • 個別の株式：検索で銘柄コードを特定してから、同じくYahoo FinanceのAPIで現在の値を取得します
  • 天気：気象庁（JMA）の公式予報JSONを主軸に取得します。主要都市は地域コードで直接、その他の場所は位置情報サービスと組み合わせ、失敗したら都道府県単位の予報に切り替えます。検索で天気を調べる方法は「明日の予報」がうまく取れず、何度も失敗したため、この直接取得方式に落ち着きました

自動で振り分ける仕組みも入れました。天気・為替・株価・ニュースといったキーワードを含む質問は、先回りして該当データを取得してからAIに答えさせます。利用者は入口を意識せず、普通に質問するだけでよくなります。

「味気ない答え」を直す ― ペルソナの設定

機能が揃った段階で、ユーザー（筆者自身）から「AIの回答が味気なさすぎる」という感想が出ました。そこで、ボットに人格設定（ペルソナ）を与えました。

設定は「小学5年生の男の子」です。一人称は「ぼく」、短い文とやさしい言葉で、ひらがなを多めに、身近な例えで説明します。ただし、数字・日付・出典リンクの正確さは落とさない、という条件付きです。かわいく崩しすぎて情報が不正確になっては本末転倒だからです。

この設定は、通常回答・検索・天気・株価など、すべての入口で共通に効くよう、指示文を1か所にまとめて適用しました。入口ごとに人格がブレないための工夫です。結果として、正確さは保ったまま、読みやすい答えが返るようになりました。ペルソナは好みでよいと思いますが、「正確さの条件とセットで書く」ことだけは、どんな設定でもおすすめします。

おまけの機能：ダイエット記録

運用が安定してから、食事記録の機能も足しました。仕組みだけ簡単に紹介します。

  • 記録は /gohan というスラッシュコマンド専用にしました。メンションでの記録は受け付けません（質問と記録が混ざると誤作動のもとになるためです）。写真からの記録も対応していません
  • 記録先は、ボットが投稿する専用の「ダイエット記録」チャンネルです。データベースを持たず、チャンネルへの投稿そのものを記録として使う設計で、無料枠の範囲に収めています
  • 1日の区切りは深夜0時ではなく、朝4時（JST）から翌朝4時までにしました。夜更かしした日の夕食が「翌日扱い」にならないための配慮です
  • ほかに、体重記録、目標設定、当日・週間の集計、取り消し、朝8時と夜21時のリマインドを用意しました

つまずきポイントのまとめ

最後に、この構築で実際に止まった場所を一覧にします。同じ道を通る人の参考になれば幸いです。

  1. モデルの無料枠が0だった：モデルごとに無料枠は別。構築前にレート制限画面で確認する（手順3）
  2. MESSAGE CONTENT INTENT の付け忘れ：ボットが本文を読めない。真っ先に確認する（手順1）
  3. pushしてもデプロイされない：公開リポジトリURL指定の接続では手動再デプロイが必要（手順5）
  4. 環境変数の名前違い・空白混入：起動直後に落ちる原因の定番（手順5）
  5. ログに出力が溜まって見えない：行単位の即時出力に設定する（手順5）
  6. ボットが無言で止まったことがある：無料枠側の再起動で自動復帰しました。データの損失はありませんでしたが、「止まる前提で、気づける仕組み（ログと死活確認）を持つ」ことが大事だと分かりました

まとめ

無料枠だけでも、検索・天気・株価まで答える実用的なDiscordボットが作れます。手順の山場は、Discord側の権限設定（特にMESSAGE CONTENT INTENT）、モデルの無料枠の事前確認、そしてRenderの環境変数です。逆に言えば、この3点を押さえれば、あとは順番に進めるだけです。

残る大きな課題は「眠る」ことです。Renderの無料枠は約15分でスリープし、復帰に30秒ほどかかります。この対策（10分おきの死活確認と、その見守りの二重化）は、別の記事「無料サーバーはなぜ眠るのか ― スリープの仕組みと対策」に手順レベルでまとめました。あわせて読んでもらえると、無料運用の全体像がつながります。

※各サービスの無料枠・料金・条件は2026年11月26日時点の情報です。変更されることがあるため、始める前に公式サイトで最新の条件をご確認ください。
